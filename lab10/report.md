## 1. Objectives and Theoretical Background

### 1.1 Laboratory Objectives
While Laboratory Work No. 9 used `strace` to inspect Linux system calls from outside the kernel via `ptrace()`, Laboratory Work No. 10 implements an in-kernel tracing mechanism directly inside **xv6-riscv** by adding a brand-new system call, `trace(int mask)`, along with its user-space wrapper utility `/trace`. The objectives are:
- **User-Space Syscall Plumbing:** Defining the new system call number (`SYS_trace = 23`), declaring its C prototype (`int trace(int);`), generating its RISC-V assembly stub via `user/usys.pl`, and registering the `trace` user binary in the `Makefile`.
- **Kernel Dispatch & Process State:** Extending `struct proc` with a per-process `trace_mask`, implementing `sys_trace()` in `kernel/sysproc.c`, registering it in `syscalls[]` and `syscallnames[]`, and printing matching syscalls from `syscall()` in `kernel/syscall.c`.
- **Mask Propagation Across `fork()` and `exec()`:** Ensuring forked children inherit the parent's `trace_mask` (`kfork()` in `kernel/proc.c`) and that `exec()` preserves `trace_mask` on the same `struct proc`.
- **Live Verification in QEMU:** Running `grep`, `usertests forkforkfork`, and `echo` under different bitmasks and analyzing the resulting traces and timing behavior.

### 1.2 Syscall Call Path and Bitmask Encoding
When user code invokes `trace(mask)`, the RISC-V assembly stub generated by `user/usys.pl` loads `a7 = SYS_trace` (`23`), preserves the argument `mask` in `a0`, and executes `ecall`. The kernel trap handler enters `syscall()` (`kernel/syscall.c`), reads `num = p->trapframe->a7`, validates bounds (`num > 0 && num < NELEM(syscalls) && syscalls[num]`), executes `p->trapframe->a0 = syscalls[num]()`, and checks whether bit `num` is enabled in `p->trace_mask`:

```c
if ((p->trace_mask >> num) & 1)
  printk("%d: syscall %s -> %ld\n", p->pid, syscallnames[num],
         p->trapframe->a0);
```

Key system call numbers in `kernel/syscall.h` and their corresponding single-bit masks ($2^{\text{num}}$):

| Constant | Number | Bitmask ($2^n$) | Hexadecimal | Role in Lab 10 |
| --- | :---: | :---: | :---: | --- |
| `SYS_fork` | 1 | `2` | `0x00000002` | Tested with `trace 2 usertests forkforkfork` |
| `SYS_read` | 5 | `32` | `0x00000020` | Tested with `trace 32 grep hello README` |
| `SYS_exec` | 7 | `128` | `0x00000080` | Observed under `trace 2147483647` |
| `SYS_open` | 15 | `32768` | `0x00008000` | Observed under `2147483647`; part of `open \| close` |
| `SYS_write` | 16 | `65536` | `0x00010000` | Tested with `trace 65536 echo hi` |
| `SYS_close` | 21 | `2097152` | `0x00200000` | Observed under `2147483647`; part of `open \| close` |
| `SYS_trace` | 23 | `8388608` | `0x00800000` | Newly added syscall (traces itself under `2147483647`) |
| All (1–23) | 1..30 | `2147483647` | `0x7fffffff` | Tested with `trace 2147483647 grep hello README` |

## 2. Part 1: User-Side Plumbing and `user/trace.c`

### 2.1 Syscall Number, Prototype, Assembly Stub, and Makefile
The user-space wiring spans four files in `~/xv6-riscv`:
1. **`kernel/syscall.h`**: `#define SYS_trace 23` appended after `#define SYS_sync 22`.
2. **`user/user.h`**: `int trace(int);` added directly below `int sync(void);`.
3. **`user/usys.pl`**: `entry("trace");` appended at the end so `make` emits `.global trace`, `li a7, SYS_trace`, `ecall`, `ret` into `user/usys.S`.
4. **`Makefile`**: `$U/_trace\` added to `UPROGS` right after `$U/_zombie\`.

### 2.2 The `trace` Command (`user/trace.c`)
`user/trace.c` validates that at least a mask and command are provided, enables tracing on the current process via `trace(atoi(argv[1]))`, and then calls `exec(argv[2], argv + 2)` to replace the image while retaining `p->trace_mask`:

```c
#include "kernel/types.h"
#include "kernel/stat.h"
#include "user/user.h"

int
main(int argc, char *argv[])
{
  if (argc < 3) {
    fprintf(2, "usage: trace mask command [args...]\n");
    exit(1);
  }
  if (trace(atoi(argv[1])) < 0) {
    fprintf(2, "trace: failed\n");
    exit(1);
  }
  exec(argv[2], argv + 2);
  fprintf(2, "trace: exec %s failed\n", argv[2]);
  exit(1);
}
```

*(Note: Running `trace 32 grep hello README` before adding kernel-side dispatch triggers `unknown sys call 23` and `trace: failed` because `syscalls[23]` does not yet exist in `kernel/syscall.c`.)*

## 3. Part 2: Kernel Implementation

### 3.1 Process State and `fork()` Inheritance
- In **`kernel/proc.h`** (`struct proc`, line 104):
  ```c
  char name[16];               // Process name (debugging)
  int trace_mask;              // which calls to print
  ```
- In **`kernel/proc.c`** (`kfork()`, line 291):
  ```c
  safestrcpy(np->name, p->name, sizeof(p->name));
  np->trace_mask = p->trace_mask;
  ```
  Because `np->trace_mask` copies `p->trace_mask` from parent to child, any child created by a traced process automatically emits trace lines without calling `trace()` itself, whereas children of the untraced shell continue with mask `0`.

### 3.2 `sys_trace` Handler (`kernel/sysproc.c`)
```c
uint64
sys_trace(void)
{
  int mask;
  argint(0, &mask);
  myproc()->trace_mask = mask;
  return 0;
}
```

### 3.3 Dispatch Table, Name Table, and Logging (`kernel/syscall.c`)
In `kernel/syscall.c`, `extern uint64 sys_trace(void);` is declared (line 106), `[SYS_trace] = sys_trace` is added to `syscalls[]` (line 134), and `syscallnames[]` maps each syscall number (`SYS_fork` through `SYS_trace`) to its printable name:

```c
static char *syscallnames[] = {
  [SYS_fork] "fork",   [SYS_exit] "exit",     [SYS_wait] "wait",
  [SYS_pipe] "pipe",   [SYS_read] "read",     [SYS_kill] "kill",
  [SYS_exec] "exec",   [SYS_fstat] "fstat",   [SYS_chdir] "chdir",
  [SYS_dup] "dup",     [SYS_getpid] "getpid", [SYS_sbrk] "sbrk",
  [SYS_pause] "pause", [SYS_uptime] "uptime", [SYS_open] "open",
  [SYS_write] "write", [SYS_mknod] "mknod",   [SYS_unlink] "unlink",
  [SYS_link] "link",   [SYS_mkdir] "mkdir",   [SYS_close] "close",
  [SYS_sync] "sync",   [SYS_trace] "trace",
};
```

Inside `syscall(void)` (lines 160–163), immediately after `p->trapframe->a0 = syscalls[num]();`, matching calls are logged via `printk`:

```c
    p->trapframe->a0 = syscalls[num]();
    if ((p->trace_mask >> num) & 1)
      printk("%d: syscall %s -> %ld\n", p->pid, syscallnames[num],
             p->trapframe->a0);
```

Using `%ld` ensures negative return values such as `-1` (which are stored as 64-bit `uint64` in `trapframe->a0`) print accurately in signed decimal form via `printint(..., 10, 1)` in `kernel/printk.c`.

## 4. Part 3: QEMU Execution Results and Observations

All four verification commands were compiled and run inside QEMU (`make qemu`), with verbatim outputs preserved in `results.txt`.

### 4.1 Filtering a Single System Call: `trace 32 grep hello README`
```text
$ trace 32 grep hello README
3: syscall read -> 1023
3: syscall read -> 965
3: syscall read -> 453
3: syscall read -> 0
```
- **Explanation:** `32 = 2^5`, corresponding to `SYS_read = 5`. PID `3` calls `read()` four times while scanning `README` (`1023 + 965 + 453 = 2441` bytes read before `0` indicates EOF). `grep`'s 1024-byte `buf` leaves room for `1023` bytes initially (`sizeof(buf) - m - 1`) and carries leftover incomplete line bytes `m` between reads (`1023 - 58 = 965`).

### 4.2 Tracing All Implemented Calls: `trace 2147483647 grep hello README`
```text
$ trace 2147483647 grep hello README
4: syscall trace -> 0
4: syscall exec -> 3
4: syscall open -> 3
4: syscall read -> 1023
4: syscall read -> 965
4: syscall read -> 453
4: syscall read -> 0
4: syscall close -> 0
```
- **Explanation:** `2147483647` (`0x7fffffff`, bits 0–30 set) enables every syscall 1–23:
  1. `trace` itself sets `p->trace_mask = 2147483647` inside `sys_trace()` and then immediately passes the `(p->trace_mask >> 23) & 1` check on return (`4: syscall trace -> 0`).
  2. `exec` replaces the process image with `grep` (`argc = 3`: `"grep"`, `"hello"`, `"README"`), returning `3` in `a0` (`4: syscall exec -> 3`).
  3. `grep` opens `README` on lowest unused fd `3` (`open -> 3`), performs the same four `read` calls, and closes fd `3` (`close -> 0`).
  4. `exit` is not printed because `sys_exit()` terminates the process and never returns past `p->trapframe->a0 = syscalls[num]();` in `syscall()`.

### 4.4 Post-Return Timing Interleaving: `trace 65536 echo hi`
```text
$ trace 65536 echo hi
hi67: syscall write -> 2

67: syscall write -> 1
$ 
```
- **Explanation:** `65536 = 2^{16}` traces `SYS_write = 16`. Inspecting `user/echo.c` shows `echo` executes two separate `write()` calls: `write(1, "hi", 2)` and then `write(1, "\n", 1)`. Because `syscall()` logs *after* `syscalls[num]()` completes, the first `write` emits `hi` onto the console immediately, then `printk` appends `67: syscall write -> 2\n`. Next, `echo` issues `write(1, "\n", 1)`, emitting the newline (producing the blank line) right before `67: syscall write -> 1\n`.

### 4.5 Observation Questions (`notes.txt`)
1. **In `trace 32 grep hello README` why do you see only `read`, and not `open` or `close`?**  
   Mask `32 = 2^5` has only bit `5` (`SYS_read = 5`) set. Since `SYS_open = 15` (bit 15) and `SYS_close = 21` (bit 21) correspond to zero bits in `32`, `(p->trace_mask >> num) & 1` evaluates to `0` for `open` and `close`.
2. **In `forkforkfork`, three different pids print lines. Which line of code from Part 2 makes that possible?**  
   `np->trace_mask = p->trace_mask;` in `kfork()` inside `kernel/proc.c` (line 291), which copies the parent's trace mask into each newly forked child process.
3. **In `trace 65536 echo hi` the trace line is printed between `"hi"` and the new line. Why? (How many times does `echo` call `write`?)**  
   `echo` calls `write` **2** times: once for `"hi"` (2 bytes) and once for `"\n"` (1 byte). Since `syscall()` executes `printk(...)` after `syscalls[num]()` returns, `"hi"` appears first, followed by `67: syscall write -> 2\n`, followed by the newline from the second `write`, followed by `67: syscall write -> 1\n`.
4. **Which mask traces both `open` (15) and `close` (21), and nothing else?**  
   $2^{15} + 2^{21} = 32768 + 2097152 = 2129920$ (`0x208000` in hexadecimal).

## 5. Conclusions

1. **End-to-End Syscall Integration:** Adding `trace(int)` exercised every layer of xv6's syscall path: number definitions (`kernel/syscall.h`), user prototypes and RISC-V `ecall` stubs (`user/user.h`, `user/usys.pl`), user CLI orchestration (`user/trace.c`), per-process metadata (`kernel/proc.h`), and kernel dispatch (`kernel/sysproc.c`, `kernel/syscall.c`).
2. **Process Mask Inheritance:** Keeping `trace_mask` inside `struct proc` automatically preserves tracing across `exec()` and propagates it through `kfork()` via `np->trace_mask = p->trace_mask;`, enabling multi-process tests such as `forkforkfork` without user-space instrumentation.
3. **Post-Execution Logging Semantics:** Logging inside `syscall()` after `p->trapframe->a0 = syscalls[num]()` guarantees access to return values (including `-1` formatted via `%ld` and `exec`'s `argc` return value), directly explaining both console interleaving in `echo hi` and why non-returning calls such as `exit` do not emit a post-call trace line.
4. **Bitmask Selectivity:** Encoding traced calls as a bitmask allows $O(1)$ bitwise dispatch filtering with `(p->trace_mask >> num) & 1`, scaling cleanly from single-syscall filters (`32` for `read`, `2` for `fork`, `65536` for `write`) to arbitrary combinations (`2129920` for `open | close`, `2147483647` for all calls).
